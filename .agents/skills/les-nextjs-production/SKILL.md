# LES Next.js Production Standards

## 1. Verified Workspace Architecture & Key Paths

Always reuse the existing infrastructure instead of creating parallel clients or auth helpers:

- **YARP Gateway & API Clients**
  - `lib/les-api.ts` — `fetchLesApi<T>()`, `fetchMenuApi<T>()`: Server-side fetchers targeting `process.env.API_URL` (YARP Gateway), injecting `Authorization: Bearer <jwt>` from `cookies()` and project headers (`X-Project-Name`, `x-project-id`, `x-project-code`).
  - `lib/nestjs.ts` — `fetchNestJs<T>()`, `fetchMenuNestJs<T>()`: Routes through `process.env.API_URL` with `/api/iam/...` prefix for `api-iam` endpoints.
  - `app/actions/*.ts` — Server Actions (`auth.ts`, `dashboard.ts`, `street-light.ts`, `group-config.ts`, `schedule-settings.ts`, `maintenance.ts`, `map-actions.ts`, `project-management.ts`, `setting-system.ts`).
- **Keycloak Auth & Session Handling**
  - `lib/keycloak.ts` — Keycloak Direct Access Grant, token refresh, logout, and JWT payload/role/project extractors (`getKeycloakConfig`, `loginKeycloakDirectGrant`, `refreshKeycloakToken`, `decodeJwtPayload`, `extractRolesFromPayload`, `extractAllProjectIdsFromPayload`).
  - `app/actions/auth.ts` — `login()`, `logout()`, `getCurrentUser()`, `getAuthorizedMenu()`, `refreshTokenAction()`. Stores `jwt`, `refresh_token`, and `id_token` in `httpOnly` cookies.
  - `app/api/auth/*` — Route handlers (`login`, `callback`, `logout`, `check-reset-user`, `profile-otp`, `verify-status`).
  - `proxy.ts` — Request proxy resolving multi-project context (`current_project` cookie/subdomain), validating JWT expiry, and delegating i18n routing.
  - `components/common/token-refresher.tsx` — Background 60s token refresh trigger via `refreshTokenAction()`.
- **Permission Guard (`api-iam`)**
  - `app/actions/auth.ts` (`getAuthorizedMenu`) fetches `/api/permissions/my-menus` via `fetchNestJs`.
  - `app/[locale]/(main)/layout.tsx` loads `menuItems` on the server and passes `initialPermissions` + `isSuperAdmin` to `PermissionProvider`.
  - `components/providers/permission-provider.tsx` — `PermissionProvider` and `usePermission()` (`getPermission(menuName)` -> `{ readable, writable, control }`, `getApiVersion(menuName)`).
- **Localization (`next-intl`) & Theming (`next-themes`)**
  - `i18n/routing.ts` (`locales: ['th', 'en']`, `defaultLocale: 'th'`, `localeDetection: false`), `i18n/request.ts`, `messages/th.json`, `messages/en.json`.
  - `app/[locale]/layout.tsx` — Wraps app with `ThemeProvider` (`attribute="class"`, `themes={["light", "dark", "skyblue"]}`, `suppressHydrationWarning` on `<html>`), `ProjectProvider`, and `NextIntlClientProvider`.
  - `components/providers/theme-provider.tsx`, `lib/theme.ts`, `app/globals.css`.
- **UI & Domain Components**
  - `components/ui/*` — `shadcn/ui` primitives (Radix UI + Tailwind CSS v4 + `cn()` from `lib/utils.ts`).
  - `components/layout/*` — `app-sidebar.tsx`, `site-header.tsx`, `header-breadcrumb.tsx`, `nav-user.tsx`.
  - `components/cores/*` — Feature modules (`auth`, `dashboard`, `maintenance`, `map`, `profile`, `setting-control`, `setting-system`).
  - `components/customs/*` & `lib/component-loader.tsx` — Multi-project component overrides resolved via `lib/component-registry.generated.ts` (generated by `scripts/codegen-registry.mjs` via `npm run codegen` / `predev` / `prebuild`; never edit the generated file manually).
  - `components/common/*` — `language-switcher.tsx`, `project-switcher.tsx`, `theme-switcher.tsx`, `token-refresher.tsx`, `page-unavailable.tsx`.
- **Multi-Project Resolution**
  - `config/projects.ts` (`resolveProjectUuid`, `resolveProjectSlug`, `getProjectById`, `getProjectByDomain`) and `lib/project.ts` (`getProjectConfig`, `getActiveProjectCode`, `getUserProjectIds`) — Always resolve project IDs/slugs through these helpers rather than hardcoding tenant values.

## 2. Zero-Trust Frontend Security & CVE Defense

- **Dependency Audit (`package.json`)**
  - Before installing or recommending any new npm package, verify it has no known Critical/High CVEs (`npm audit` / advisory check).
  - NEVER run `npm audit fix --force` blindly; inspect breaking changes and upgrade or override (`overrides` in `package.json`) only targeted packages safely.
- **Token & Secret Hygiene**
  - NEVER store Keycloak `access_token`, `refresh_token`, or `id_token` in `localStorage`, `sessionStorage`, or client-accessible cookies. Always use `httpOnly`, `sameSite: "lax"` (or `"strict"`), and `secure: process.env.USING_HTTPS === "true"` cookies managed server-side in `app/actions/auth.ts` / `app/api/auth/*`.
  - NEVER expose secrets, client secrets, database credentials, or internal service keys via `NEXT_PUBLIC_*` environment variables.
- **YARP Gateway & API Security**
  - All backend API calls MUST go through YARP Gateway (`process.env.API_URL` via `lib/les-api.ts` or `lib/nestjs.ts`) from Server Actions or Route Handlers — never call internal microservices directly from the browser.
  - Attach `X-Correlation-ID` (e.g., `crypto.randomUUID()` when not already propagated) to outbound gateway requests for end-to-end tracing across YARP and C#/.NET / NestJS services.
  - Explicitly handle `401` (attempt server-side refresh or redirect to `/${locale}/login`) and `403` (redirect to `/${locale}/unauthorized` or surface safe permission-denied UI) instead of silently swallowing status codes.
- **XSS & Input Validation**
  - NEVER use `dangerouslySetInnerHTML` unless the HTML is sanitized with DOMPurify first.
  - Validate all form inputs, Server Action payloads, and URL/query parameters on both Client (`react-hook-form` + `zod`) and Server Action (`zod.safeParse`) boundaries before forwarding to YARP.

## 3. Idiomatic Code & Anti Over-Engineering

- **Natural, Readable React / Next.js**
  - Write straightforward, idiomatic App Router code. Do NOT create multi-layer wrappers, premature abstractions, or single-use custom hooks that obscure data flow.
  - Separate data fetching / API services (`app/actions/`, `lib/`) and TypeScript DTO interfaces from UI rendering (`components/`). Keep page/feature UI cohesive and easy to read continuously; extract subcomponents only when genuinely reused across multiple pages or when a section is independently stateful.
- **Server vs. Client Boundary**
  - Default to React Server Components (`app/[locale]/...`) for initial data loading and permission checks.
  - Place `"use client"` only on interactive leaf components (forms, tables with sorting/pagination state, dialogs, charts, maps).
  - Modal/Dialog triggers MUST use pre-loaded props from the parent view rather than firing on-demand API fetches on click.
- **Domain Identity & Strict TypeScript**
  - Use `SN` (Serial Number) as the sole primary identifier for all IoT devices and list items (`key={item.SN}`). Never use `clientid` or `device_id`.
  - Define strict `interface` DTOs matching the C#/.NET and NestJS backend contracts. `any` is strictly forbidden (use `unknown` + narrowing when needed).
  - Satisfy `react-hooks/exhaustive-deps` cleanly (refactor with functional state updates or `useCallback` rather than disabling ESLint rules) and always use `const` unless reassignment is required.

## 4. High Performance & Scalability (10,000+ Devices)

- **Prevent Duplicate Fetches & Waterfalls**
  - Use `React.cache()` for server-side per-request deduplication (e.g., `getAuthorizedMenu`, `getCurrentUser`, `getProjectConfig`) and Next.js `fetch` caching or TanStack Query where client caching is needed. Never let multiple components redundantly fetch `api-iam` permissions or project config in parallel.
  - Do not re-fetch `getAuthorizedMenu()` on the client when `PermissionProvider` already receives `initialPermissions` from `app/[locale]/(main)/layout.tsx`.
- **Prevent Unnecessary Re-renders & Stale Requests**
  - Avoid creating inline object/function literals in render props or `useEffect` dependencies when they trigger child re-renders or effect loops.
  - Debounce search/filter inputs and pass `AbortController.signal` to cancel superseded client requests when users type rapidly or switch pages.
- **Large Tables & Heavy Visualizations**
  - Enforce server-side pagination, sorting, and filtering for device/maintenance tables — NEVER load 10,000+ rows into the browser to filter client-side.
  - Lazy-load heavy client bundles with `next/dynamic(..., { ssr: false })` for charts (`recharts`), maps (`leaflet`, `react-leaflet`, `@react-google-maps/api`, OpenLayers), and large modals/PDF renderers (`@react-pdf/renderer`).
- **Hydration Safety (`next-themes` & `next-intl`)**
  - Keep `suppressHydrationWarning` strictly on `<html>` (as in `app/[locale]/layout.tsx`) or the exact theme-dependent element — never mask real mismatches globally.
  - Extract all user-facing strings to `messages/th.json` and `messages/en.json` via `useTranslations` / `getTranslations`; never hardcode raw UI text in JSX.

## 5. Production Readiness (No Half-Measures)

- **Zero Leftover Artifacts**: Never leave `// TODO`, `// FIXME`, commented-out code blocks, or `console.log` statements in committed code.
- **Complete Async State Handling**: Every async operation and view must explicitly handle:
  1. **Loading State** (`Skeleton` / disabled pending button state)
  2. **Empty State** (clear localized empty message via `next-intl`)
  3. **Error State** (localized, user-safe error message via `sonner` toast or `Alert` — NEVER expose raw stack traces, SQL errors, or internal URLs to the UI).
- **Verification Gate**: After code edits, run `npm run lint` and `npx tsc --noEmit` to confirm zero lint warnings and zero TypeScript errors (and run `npm run codegen` / `npm run build` when modifying component registry, routes, layouts, or dependencies).
